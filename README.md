# speedtest

Консольный скрипт для замера скорости скачивания. Делает несколько последовательных запросов к указанному
адресу, дожидается полного ответа на каждый и печатает среднее время запроса, общий объём скачанных данных
и скорость.

## Требования

- Node.js ≥ 24. TypeScript запускается напрямую через встроенный в Node
  [type stripping](https://nodejs.org/api/typescript.html#type-stripping), сборка не нужна.
- `npm install` — ставит единственную runtime-зависимость, [`undici`](#зависимости).

### На чём разрабатывалось и проверялось

Разработка — Node.js 25.9.0, Windows 11 Pro (10.0.26200). Перед сдачей (15.11.2026) на каждой версии
прогнан полный набор тестов (`npm test`, 47 тестов) и реальный замер на

## Зависимости

Вся логика — методика замера, подсчёт байт, таймаут простоя, статистика, форматирование, валидация
аргументов, обработка сетевых ошибок и тесты — написана в рамках задания. Используются встроенные
возможности Node.js и одна сторонняя библиотека — `undici`.

| Что                                                                         | Откуда                 | Зачем                                           |
| --------------------------------------------------------------------------- | ---------------------- | ----------------------------------------------- |
| `fetch`, `Agent`                                                            | пакет `undici` 8       | HTTP/1.1-запросы, потоковое чтение, keep-alive  |
| `parseArgs`                                                                 | `node:util`            | разбор аргументов командной строки              |
| `performance.now()`                                                         | глобальный объект Node | точное измерение времени                        |
| `Intl.NumberFormat`                                                         | стандарт JavaScript    | форматирование чисел                            |
| `node:test`, `node:assert`, `node:http`, `node:http2`, `node:child_process` | встроенные модули Node | тесты, локальные HTTP/HTTPS-серверы, запуск CLI |

**Почему `undici`, а не встроенный `fetch`.** Встроенный `fetch` — это тоже undici, но его версия зависит
от Node: в Node 24–25 — undici 7, в Node 26 — undici 8, который по умолчанию использует HTTP/2, если
сервер его предлагает. Один поток HTTP/2 ограничен окном управления потоком (≈ окно / RTT), и на
Node 26 скрипт показывал не скорость канала, а этот предел — в ~5 раз меньше:

| Замер на `proof.ovh.net/files/10Mb.dat`           | Скорость      |
| ------------------------------------------------- | ------------- |
| Встроенный `fetch`, Node 25 (HTTP/1.1)            | ~150 Мбит/с   |
| Встроенный `fetch`, Node 26 (HTTP/2)              | ~20 Мбит/с    |
| `node:http2` напрямую, окно 64 КиБ (по умолчанию) | ~5 Мбит/с     |
| `node:http2` напрямую, окно 16 МиБ                | 82–115 Мбит/с |

Своя версия `undici` с `Agent({ allowH2: false })` делает результат независимым от версии Node и всегда
меряет обычную пропускную способность TCP-соединения по HTTP/1.1. Это закреплено тестом: CLI запускается
против HTTPS-сервера, предпочитающего HTTP/2, и сервер должен увидеть только HTTP/1.1. Заодно
`--timeout` управляет и установкой соединения — у встроенного `fetch` она всегда ограничена 10 с.

Через npm также ставятся инструменты разработки (`devDependencies`) — в работе скрипта они не участвуют:

| Пакет                                       | Зачем                                 |
| ------------------------------------------- | ------------------------------------- |
| `typescript`, `@types/node`                 | проверка типов (`tsc --noEmit`)       |
| `eslint`, `@eslint/js`, `typescript-eslint` | линтер со строгими правилами и типами |
| `prettier`                                  | форматирование кода                   |

Почему без `axios`, `commander`, `jest` и т.п.: `fetch` умеет потоковое чтение и отмену запроса,
`parseArgs` хватает для трёх опций, `node:test` — полноценный тест-раннер. Другие библиотеки добавили бы
зависимости без выигрыша.


## Единицы измерения

Все единицы десятичные (SI) — так скорость указывают провайдеры и сервисы замера скорости.

| Величина        | Единица               | Определение                            |
| --------------- | --------------------- | -------------------------------------- |
| Скорость        | **Мбит/с** (`Mbit/s`) | 1 Мбит/с = 10⁶ бит в секунду           |
| Скорость (доп.) | МБ/с (`MB/s`)         | 1 МБ/с = 10⁶ байт в секунду = 8 Мбит/с |
| Объём           | B, kB, MB, GB, TB     | 1 kB = 10³ байт, 1 MB = 10⁶ байт, …    |
| Время           | мс (`ms`)             |                                        |

Вывод на английском и с фиксированной локалью форматирования чисел (`en-US`): так он одинаково читается
в любой консоли, в том числе в Windows-терминалах с не-UTF-8 кодировкой.

## Методика

- **Время запроса** — от отправки запроса до получения последнего байта тела ответа (`performance.now()`).
- **Объём** — сумма байт тела, реально прочитанных из потока, а не значение `Content-Length`.
- **Скорость** = общий объём / суммарное время всех запросов. Это не среднее скоростей отдельных
  запросов: такое среднее завышает результат, потому что быстрый и медленный запрос весили бы одинаково,
  хотя медленный занимал канал дольше.
- Запросы строго последовательные, тело читается потоком и не держится в памяти — можно мерить
  на файлах любого размера.
- Запрос отправляется с `Accept-Encoding: identity` (чтобы считать байты без сжатия) и
  `Cache-Control: no-cache`.
- **Всегда HTTP/1.1**, даже если сервер предлагает HTTP/2 — см. [почему](#зависимости).
- **Таймаут** — это таймаут простоя: запрос прерывается, если данные не приходят дольше `--timeout`
  (включая установку соединения). Общий таймаут на запрос обрывал бы медленное, но идущее скачивание
  большого файла, а задача таймаута — ловить зависшие соединения.

## Сбои сети

Любой сбой прерывает замер с кодом выхода `1` и понятным сообщением: что случилось, что проверить
и технические детали в скобках. Строки уже завершённых запросов остаются в выводе.

| Ситуация                                            | Что видит пользователь                                                               |
| --------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Нет интернета с самого начала (адрес по имени)      | `could not resolve the host name — check the URL and your internet connection (...)` |
| Нет интернета, адрес — IP                           | `the network is unreachable …` или `No data received for 30 s …` (по `--timeout`)    |
| Соединение оборвалось посреди скачивания            | `the connection was lost — check your internet connection (...)`                     |
| Сеть пропала «молча» — данные просто перестали идти | `No data received for 30 s — the connection may have been lost …` (по `--timeout`)   |
| Соединение умерло между запросами                   | Ничего: `fetch` прозрачно открывает новое соединение, замер продолжается             |

Решения:

- **Частично скачанный ответ не засчитывается.** Иначе объём был бы занижен, а скорость — искажена.
- **Без повторов.** Повтор после обрыва смешал бы в результате время восстановления сети со скоростью
  канала; честнее сообщить о сбое и дать перезапустить замер.

Пример:

```console
$ npm start -- https://no-such-host.invalid/
Downloading https://no-such-host.invalid/ 10 times...

Request 1/10 failed: Network error: could not resolve the host name — check the URL and your internet connection (getaddrinfo ENOTFOUND no-such-host.invalid)
```

## Архитектура

```
src/
  cli.ts              точка входа: связывает модули, вывод, коды выхода
  config.ts           разбор и валидация аргументов → help | measure(Config)
  measurement.ts      последовательные замеры через интерфейс Downloader
  downloader.ts       интерфейс Downloader и реализация на undici fetch (HTTP/1.1): поток, байты, таймаут
  network-failure.ts  перевод сетевых ошибок fetch в понятные сообщения
  stats.ts            summarize(samples) → Summary — чистая функция
  format.ts           форматирование единиц и отчёта — чистые функции
  sample.ts           тип одного замера
  units.ts            константы единиц
  errors.ts           UsageError; DownloadError и наследники
```

Зависимости направлены внутрь: `cli` → `measurement` → интерфейс `Downloader`. Расчёты и форматирование
не знают ни о сети, ни о консоли. Точки расширения:

- другой способ скачивания (свой HTTP-клиент, другой протокол) — новая реализация `Downloader`;
- другой формат вывода (например, JSON для скриптов) — новый форматтер поверх того же `Summary`.

## Решения и компромиссы

- **Одна runtime-зависимость — `undici`**, чтобы результат не зависел от версии Node и протокола,
  который выберет сервер — см. [Зависимости](#зависимости).
- **Без сборки.** Node запускает `.ts` напрямую; `tsc` используется только для проверки типов. Цена —
  только «стираемый» синтаксис TypeScript (без `enum`, parameter properties), это контролирует
  `erasableSyntaxOnly`.
- **TypeScript 6.0, а не 7.0.** TS 7 уже вышел, но `typescript-eslint` пока поддерживает только `< 6.1`.
  Линтинг с проверкой типов оказался важнее новой версии компилятора; переход на 7 — когда его поддержит
  `typescript-eslint`.

## Ограничения

- **Один поток.** Замер идёт по одному соединению. Сервисы вроде Speedtest используют несколько
  параллельных потоков, поэтому на быстрых каналах с большой задержкой результат будет ниже предельной
  скорости канала.
- **Скорость до конкретного сервера.** Результат ограничен и сервером/CDN, с которого идёт скачивание.
- **Установка соединения.** Соединение переиспользуется (keep-alive), поэтому первый запрос дополнительно
  включает DNS, TCP и TLS и обычно заметно медленнее — это видно в примере выше. Время всех запросов
  включает и время ответа сервера (TTFB), и редиректы, если они есть.
- **Сжатие.** `fetch` прозрачно распаковывает сжатые ответы. Если сервер проигнорирует
  `Accept-Encoding: identity` и всё равно сожмёт ответ, будет посчитан распакованный объём. Для бинарных
  файлов (картинки, архивы, видео) на практике не встречается.
- **URL с учётными данными** (`https://user:password@host/…`) отклоняются с кодом `2`: `fetch` по
  стандарту их не принимает, а сообщение об ошибке не повторяет адрес, чтобы пароль не попал в логи.

## Что можно улучшить

- Отдельно показывать время до первого байта и время передачи.
- Опциональный «прогревочный» запрос, не входящий в статистику.
- Параллельные потоки (`--parallel`) для замера предельной скорости канала.
- Вывод в JSON (`--json`) для использования в скриптах и мониторинге.
- Basic-авторизация для URL с учётными данными (как в `curl`) — через заголовок `Authorization`.
